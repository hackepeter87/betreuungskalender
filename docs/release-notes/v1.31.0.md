# v1.31.0

`v1.31.0` simplifies the creation of recurring care schedules in the
self-hosted application. The common workflow now starts with the people and
the first appointment, then offers familiar repeat choices and a readable
preview before saving.

## Recurring care workflow

- Select the children and responsible care party before defining the first
  appointment.
- Choose a one-time, weekly, biweekly, monthly, or custom recurrence.
- Review a plain-language summary and the next representative occurrences
  before saving the series.
- Use a guided four-step flow on compact screens without hiding the complete
  form on desktop.

## Advanced and historical management

- Existing advanced monthly rules and additional care periods remain
  available without appearing in the common workflow.
- Saved advanced rules remain editable without rewriting their recurrence
  definition.
- Historical backfill remains preview-first and explicitly confirmed, but is
  now presented as a separate collapsed management action.
- Existing manual changes, cancellations, conflicts, and historical records
  remain protected.

## Validation and compatibility

- Recurrence parity covers weekly, biweekly, monthly, one-time, custom, and
  multi-day appointments.
- Browser validation covers desktop, iPhone, iPad, six responsive viewports,
  accessibility, localization, and keyboard behavior.
- Runtime, security, SQLite, PostgreSQL 16 and 18, container, Helm, CodeQL,
  dependency, and image checks remain enforced.

The Helm chart is `0.12.0` with application version `1.31.0`. This release has
no database migration and no intentional API, authentication, or deployment
compatibility break.

The release is published first to `testing`. Promotion to `production` or
`latest` requires a separate explicit approval.
