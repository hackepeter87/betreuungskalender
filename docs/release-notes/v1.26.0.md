# v1.26.0

`v1.26.0` establishes a maintainable frontend baseline for the self-hosted
application without changing its domain data model or authentication flows.

## Shared styles and responsive layout

- Application styles now follow an explicit layer order for tokens, browser
  defaults, the application shell, shared components, feature pages,
  responsive rules, utilities, and print output.
- Shared page, panel, form, action, and typography rules have one documented
  owner instead of relying on release-specific override blocks.
- The responsive More menu restores keyboard focus when it closes and handles
  Escape consistently.
- Tablet-width CSV export controls remain within their settings grid.
- The application font is bundled locally for consistent rendering without an
  external font request.

## Deferred loading and offline behavior

- The dashboard and first-use setup remain in the initial application bundle.
- Secondary pages, report views, analytics, and PDF dependencies load only
  when opened.
- Previously loaded deferred assets can be served by the application cache.
  Pages that have not been downloaded still require a network connection, and
  API-backed offline use remains read-only.
- A shared accessible loading and failure surface handles deferred pages.

## Regression coverage and repository hygiene

- Deterministic browser baselines cover dashboard, calendar, settings, report,
  backup, and responsive navigation at 320, 390, 768, 1280, 1440, and 1920 CSS
  pixels.
- Semantic checks cover horizontal overflow, covered controls, responsive
  overlays, keyboard focus, and Escape behavior. Print validation remains a
  separate test surface.
- Baselines use fictional records only. Generated reports, databases,
  downloads, and temporary review output remain outside release artifacts.
- Obsolete compatibility helpers and their dead tests have been removed while
  supported role compatibility remains unchanged.

## Compatibility and upgrade

No database migration, API change, or configuration migration is required.
Existing data, backups, portable transfers, memberships, invitations, feeds,
and authentication modes remain compatible.

The Helm chart is updated to `0.7.0` with application version `1.26.0`.

## Validation

The release is validated with type checks, unit and integration tests, browser
tests at all documented viewport widths, visual regression review, runtime
security checks, container and Helm smoke tests, bundle analysis, dependency
analysis, CodeQL, and strict release checks. Published artifacts are promoted
only to the `testing` channel for separate runtime acceptance. The `production`
and `latest` channels remain unchanged.
