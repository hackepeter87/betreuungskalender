# v1.34.0

`v1.34.0` adds an owner-guided workflow for reviewing and applying approved
privacy lifecycle actions in a self-hosted installation.

## Review before action

- Owners can inventory relevant records and dependencies before changing data.
- A dry-run preview summarizes the proposed effect, warnings, blockers, and
  retained records without modifying the database.
- Applying a change requires an explicit confirmation and the exact preview
  fingerprint. Concurrent changes invalidate the preview instead of producing
  a partial result.

## Controlled lifecycle actions

- Current workspace access and authentication identities can be revoked before
  later lifecycle steps are considered.
- Approved identity and profile attributes can be anonymized while protected
  historical and shared-domain references remain consistent.
- Approved domain data can be removed transactionally when no documented
  safeguard blocks the operation.
- Repeated requests are idempotent, and failed operations roll back without
  leaving a partially updated lifecycle state.

## Operator guidance

- Backup, restore, export, and portable transfer documentation explains which
  copies require separate operator handling after an approved action.
- The application does not choose retention periods, infer a legal basis, or
  claim that one technical action satisfies every privacy request.
- Technical responses and logs contain aggregate results and stable error codes
  instead of personal record content or authentication identifiers.

## Compatibility

- SQLite and PostgreSQL use equivalent migrations and lifecycle behavior.
- Migrations `035` and `036` add bounded action state and permit approved
  anonymization of child birth attributes.
- Existing installations, backups, exports, and portable transfer packages
  remain supported.

The Helm chart is `0.15.0` with application version `1.34.0`. The release is
published first to `testing`. Promotion to `production` or `latest` requires a
separate explicit approval.
