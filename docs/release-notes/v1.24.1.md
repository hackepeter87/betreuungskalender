# v1.24.1

`v1.24.1` strengthens external calendar retrieval and keeps authenticated
application routes on one consistent access-control baseline.

## External calendars

- External HTTPS calendar sources are checked again after each redirect.
- All resolved addresses must be suitable for a public HTTPS connection.
- Redirect count, request duration, and compressed and decoded response sizes
  are bounded.
- Unavailable or rejected sources return a generic message without disclosing
  source details.

## Access control

- Protected application routes use a shared registry for their required
  permissions.
- The server validates protected-route coverage during startup.
- Public and pre-authentication routes remain explicit, and the supported
  Local, Native OIDC, and Trusted Proxy modes retain their existing behavior.

## Compatibility

No database migration is required. Existing application data, memberships,
invitations, backups, portable transfers, and valid external calendar
configurations remain compatible.

The Helm chart is updated to `0.5.1` with application version `1.24.1`.

## Validation

The release is validated with unit and integration tests, browser checks,
runtime security tests, container and Helm smoke tests, dependency auditing,
CodeQL, and strict release checks. Published artifacts are promoted to the
`testing` channel for separate runtime acceptance before the release package is
closed.
