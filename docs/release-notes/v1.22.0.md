# v1.22.0

`v1.22.0` adds a portable, OIDC-independent path for transferring complete
domain data between self-hosted installations.

## Changes

- Export a versioned package containing domain records, audit history, and
  historical actor snapshots while excluding sessions, identity-provider
  subjects, tokens, runtime secrets, push subscriptions, personal feed tokens,
  and private external-calendar feed URLs.
- Require a dry run before every import. The dry run validates package limits,
  checksum, references, current database schema, foreign keys, and SQLite
  integrity without changing the target installation.
- Revalidate the exact package fingerprint during the real import and replace
  domain data in one transaction.
- Let the target owner explicitly map historical actors to existing members or
  create role-specific invitations. Names and email hints never grant access
  automatically.
- Use the same validation and import core for integrated fictional demo data.
- Allow the native-OIDC display-name claim to be configured independently from
  the stable technical subject.

## Compatibility

Existing SQLite backups and legacy application JSON exports remain usable.
Legacy JSON also requires a dry run but does not include historical actor
snapshots. The target owner remains unchanged, and active identities, sessions,
feed tokens, push subscriptions, and external feed connections are not moved.

The Helm chart is updated to `0.3.0` with application version `1.22.0`.

## Validation

The release is validated with linting, unit and integration tests, browser
tests, the production build, runtime security tests, container and Helm smoke
tests, dependency auditing, and strict release checks.
