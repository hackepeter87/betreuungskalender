# v1.33.0

`v1.33.0` makes changes to recurring care predictable and consolidates backup
feedback on the overview.

## Recurring-care changes

- Editing a generated occurrence now offers three explicit scopes: only this
  occurrence, this and following occurrences, or the whole series.
- A preview shows the affected period, occurrence counts, preserved records,
  warnings, and conflicts before any write is performed.
- A single-occurrence change remains a manual exception when its series is
  synchronized later.
- A whole-series change reconciles only open generated occurrences.
- A change to this and following occurrences ends the earlier rule before the
  selected occurrence and creates a successor rule for the remaining period.
- Completed, partially completed, cancelled, deleted, and manually changed
  records are never silently rewritten by a series change.

## Overview and accessibility

- Backup health appears once at the end of the overview, together with the
  latest documented portable JSON export and the existing action when the
  current user has permission.
- The recurring-care scope dialog uses consistent readable text contrast.
- Keyboard focus, escape behavior, touch layouts, and horizontal overflow are
  covered at the supported mobile, tablet, and desktop widths.

## Reliability and compatibility

- Preview fingerprints cover the selected occurrence, rule revision, relevant
  stored occurrences, child assignments, and conflict evidence.
- The write repeats the preview inside one SQLite or PostgreSQL transaction and
  rejects concurrent changes without partial writes.
- Automated acceptance covers all three scopes on SQLite, PostgreSQL 16 and 18,
  responsive browsers, runtime security, CodeQL, Trivy, containers, and Helm.
- Compatible patch-level dependencies and the supported Node.js 24 container
  baseline are refreshed.
- No database migration or authentication change is required.

The Helm chart is `0.14.0` with application version `1.33.0`. The release is
published first to `testing`. Promotion to `production` or `latest` requires a
separate explicit approval.
