# v1.10.0 - Trusted proxy hardening and UI bugfix rollup

## Summary

`v1.10.0` is a bugfix and hardening release for the current production line. It
adds an explicit trusted-proxy source allowlist and fixes several mobile and
desktop layout defects reported after the `v1.9.x` release.

The release does not include secrets, real user data, databases, backups,
exports, or deployment-specific values.

## Security hardening

- Added `TRUSTED_PROXY_CIDRS` for `AUTH_MODE=trusted-proxy` deployments.
- When configured, trusted identity headers are accepted only from matching
  socket source IP addresses or CIDR ranges.
- Invalid trusted-proxy allowlist entries fail startup validation.
- The documentation now clarifies that `TRUSTED_PROXY_CIDRS` accepts only IP
  addresses and CIDR ranges, not DNS names, Compose service names, or container
  names.

## UI fixes

- Moved upcoming care entries higher on the dashboard.
- Made the dashboard "open appointments" metric actionable by opening the
  entries view.
- Integrated the desktop notification entry into the sidebar and removed the
  stale local SQLite info card from the sidebar.
- Tightened mobile layout for calendar, agenda, entries filters, settings,
  external calendars, calendar feeds, backup actions, reports, audit log,
  holidays, and unavailability views.
- Clarified in-app notification timing and channel editability in Settings.

## Upgrade notes

- New optional environment variable:
  - `TRUSTED_PROXY_CIDRS`
- Native OIDC deployments with `TRUST_PROXY_AUTH=false` do not need to set this
  variable.
- Trusted-proxy or oauth2-proxy deployments should set it to the actual proxy
  source IP/CIDR or the smallest isolated private container-network CIDR used
  for trusted proxy traffic.
- No database migration is required beyond the existing migrations already in
  the release line.
- Publishing this release does not update `latest`; `latest` remains
  production-only and moves only with the production promotion workflow.
