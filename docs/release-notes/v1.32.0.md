# v1.32.0

`v1.32.0` keeps care-confirmation tasks consistent with direct entry changes
and adds an optional, privacy-preserving email channel for self-hosted
installations.

## Consistent care confirmations

- Completing, partially completing, or cancelling planned care now retires all
  related open confirmation tasks in the same transaction.
- A later stale answer or reminder cannot overwrite an entry that has already
  been resolved.
- Returning an entry to the planned state can create one new actionable task
  per eligible member without duplicating existing tasks.
- In-app and push behavior continue to follow permissions, conflicts, snooze
  state, and current task eligibility.

## Optional notification email

- Operators can enable notification email independently from invitation email
  with `NOTIFICATION_EMAIL_ENABLED=true` after SMTP is configured.
- The channel remains disabled by default, and every supported event remains
  opt-in for each member.
- The current account email is resolved immediately before delivery and is not
  copied into delivery-state records.
- Messages contain only a generic prompt and a link to the authenticated
  application. They contain no child names, care periods, locations, notes,
  conflict details, tokens, tracking pixels, or external templates.
- Failed delivery is retried within a bounded schedule without blocking the
  in-app task or creating duplicate successful mail.

## Operations and compatibility

- Invitation and notification mail use the same hardened, provider-neutral
  SMTP transport while retaining separate operator switches.
- Migration `034` adds technical delivery state for SQLite and PostgreSQL. It
  stores no recipient address, message content, SMTP credentials, or case data.
- Existing notification preferences, invitations, authentication modes,
  backups, and portable transfers remain compatible.
- Automated acceptance covers SQLite, PostgreSQL 16 and 18, responsive
  settings, accessibility, runtime security, CodeQL, container operation, and
  release-image validation.

The Helm chart is `0.13.0` with application version `1.32.0`. The release is
published first to `testing`. Promotion to `production` or `latest` requires a
separate explicit approval.
