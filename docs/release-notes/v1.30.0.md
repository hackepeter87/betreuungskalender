# v1.30.0

`v1.30.0` adds an operational assurance baseline for the self-hosted
application. It improves diagnostics, optional monitoring, database-aware
migration behavior, type safety, dependency maintenance, and bounded runtime
processing without changing the application's domain model.

## Diagnostics and optional metrics

- HTTP responses carry a bounded request identifier for correlation. Runtime
  logs use structured event codes and normalized route templates without
  request bodies, raw targets, identity claims, tokens, or domain values.
- An optional Prometheus-compatible listener can be enabled on a separate
  private port. It is disabled by default, requires a bearer token from a
  mounted file, and is not exposed by the application ingress.
- Metric labels remain bounded and exclude users, children, calendar content,
  URLs, IP addresses, request identifiers, credentials, and free text.

## Database and migration behavior

- Legacy browser-data migration now reports explicit capabilities for the
  selected database. Preview and additive import remain available with SQLite
  and PostgreSQL.
- Replacement after an application-created backup remains SQLite-only. The
  PostgreSQL interface does not offer that action, and unsupported direct API
  requests are rejected without changing data.
- PostgreSQL 16 and 18 continue to use the same domain and transfer contracts as
  SQLite while retaining their database-specific backup and restore procedure.

## Runtime and maintenance safeguards

- Transfer approval and historical-actor mapping are bound to the reviewed
  package and current target state.
- Notifications, personal calendar feeds, legacy migration, schedule queries,
  actor lookup, native OIDC rate-limit identities, and sensitive browser
  responses use explicit authorization, origin, cache, and processing limits.
- Maintained TypeScript projects apply checked indexed access, exact optional
  property semantics, and type-aware linting at external data boundaries.
- Dependency updates are proposed in bounded review units. They cannot merge,
  tag, publish, or promote a release automatically.

## Compatibility and validation

The Helm chart is `0.11.0` with application version `1.30.0`. This release has
no database migration and no intentional API compatibility break. SQLite
remains the default persistence backend; PostgreSQL 16 through 18 remains an
explicit option.

The release commit is validated with documentation, lint, unit, build,
browser, runtime-security, PostgreSQL 16 and 18, container, PostgreSQL
container, Helm, dependency, CodeQL, and image checks. This automated coverage
does not replace operator validation of an actual PostgreSQL installation.

The release is promoted first to `testing`. Manual PostgreSQL validation of the
published testing image remains required before any later promotion to
`production` or `latest`.
