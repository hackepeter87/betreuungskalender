# v1.26.1

`v1.26.1` adds operator-managed legal information and makes optional browser
cache storage explicit for the self-hosted application.

## Operator legal information

- Operators can provide reviewed plain-text `impressum.txt` and
  `datenschutz.txt` files through the read-only `LEGAL_CONTENT_DIR` mount.
- Public `/impressum` and `/datenschutz` pages remain available before login,
  create no application session, escape file content, and return `no-store`.
- Missing, malformed, or oversized files fail with a neutral response.
- Clearly incomplete German templates cover generally relevant operator and
  privacy-information categories without prescribing deployment-specific legal
  bases, retention periods, recipients, or provider details.
- Docker, Compose, Podman, Helm, and identity-provider footer integration use
  one operator-controlled canonical copy of each text.

The templates are starting points, not legal advice or publication-ready text.
Every placeholder and unused conditional section must be resolved, and the
actual installation text requires deployment-specific review before use.

## Browser storage

- Ordinary browser visits no longer activate optional service-worker cache
  storage automatically.
- Accepted PWA installation, standalone use, and explicit Push activation can
  enable the cache. Existing Push subscriptions remain functional.
- API, authentication, onboarding, recovery, and operator legal requests stay
  network-only. Responses marked `no-store` are never cached.
- Opaque session and recovery cookies and local interface preferences remain
  separate from optional PWA cache storage. The application includes no
  analytics or advertising storage.

## Retention and privacy roles

- A purpose-based operator matrix distinguishes live domain data, audit
  history, reports, exports, portable transfers, backups, and operational logs.
- The guide distinguishes soft delete, erasure, anonymization, backup expiry,
  and restore reconciliation without claiming that the current application
  performs selective GDPR erasure.
- Controller, joint-controller, processor, recipient, and international-
  transfer decisions remain specific to the actual installation.

## Compatibility and upgrade

No database migration or domain API change is required. Existing data,
memberships, authentication modes, invitations, feeds, backups, and portable
transfers remain compatible.

The Helm chart is updated to `0.7.1` with application version `1.26.1`. The new
legal-content mount is optional; installations without reviewed files receive a
neutral response on the corresponding public pages.

## Validation and rollout

The release is validated with type checks, unit and integration tests, browser
tests, runtime-security checks, container and Helm smoke tests, CodeQL, strict
release checks, and read-only legal-content mount tests. Publication remains
blocked until the testing installation's completed operator text and retention
choices have received manual operator/legal review. `production` and `latest`
remain unchanged.
