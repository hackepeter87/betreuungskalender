# v1.28.0

`v1.28.0` adds PostgreSQL 16 through 18 as an optional persistence backend for
the self-hosted application. SQLite remains the zero-configuration default and
existing SQLite installations require no new database setting.

## Optional PostgreSQL backend

- The application can use an explicitly selected PostgreSQL database through
  the same domain, identity, reporting, and transfer contract as SQLite.
- PostgreSQL startup applies an ordered schema under a serialized migration
  lock and keeps readiness unavailable until database access and migrations are
  complete.
- Passwords are read from mounted files. Verified TLS with a mounted CA is the
  default for remote PostgreSQL services.
- PostgreSQL does not enable horizontal application scaling. Every supported
  database mode continues to use one application replica per installation.

## Deployment options

- The base Compose definition and default Helm values remain SQLite-only.
- An opt-in Compose overlay provides a private PostgreSQL service for a
  single-host installation.
- Helm can reference an existing PostgreSQL service and existing password and
  CA Secrets without rendering credentials.
- The chart also includes a retained, single-pod PostgreSQL mode for evaluation
  only. It does not provide an operator, automatic backup, failover, high
  availability, or a production support contract.

## Data portability and parity

- Application-level parity tests exercise representative domain operations on
  SQLite, PostgreSQL 16, and PostgreSQL 18.
- Portable transfer remains the supported way to move domain data between
  SQLite and PostgreSQL. It requires the existing dry run, exact package
  fingerprint, repeated server validation, atomic replacement, and explicit
  historical-actor mapping.
- Direct SQLite file conversion, dual write, and live database replication are
  not supported.

## Backup and updates

- SQLite keeps its bundled backup, restore-check, and archive-update workflow.
- PostgreSQL requires an operator-managed logical backup and a tested restore
  before application or database updates. The SQLite maintenance scripts and
  archive updater refuse PostgreSQL installations.
- Reverting an application image or Helm release does not reverse database
  migrations. An incompatible downgrade requires a verified pre-update backup
  restored into an empty replacement database.

See [database backends](../database-backends.md) for configuration, TLS,
backup, restore, update, transfer, and troubleshooting guidance.

## Compatibility and validation

The release does not change the existing SQLite schema or default Compose and
Helm storage behavior. The Helm chart is updated to `0.9.0` with application
version `1.28.0`.

Validation covers type checks, unit and browser tests, runtime security,
container and Helm checks, PostgreSQL 16 and 18 runtime suites, cross-driver
application behavior, bidirectional portable transfer, CodeQL, Trivy, image
validation, dependency auditing, and the strict release check. Only the
`testing` channel is updated for acceptance. `production` and `latest` remain
unchanged.
