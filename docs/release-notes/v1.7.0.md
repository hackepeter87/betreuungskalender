# v1.7.0 - Care confirmation and notification preferences

## Summary

`v1.7.0` adds the first post-event confirmation workflow. Planned care entries
that are in the past can now be confirmed as completed, partially completed, or
cancelled, with optional reminder handling and per-user notification
preferences.

## Changes

- Added care confirmation requests for past planned care entries.
- Added dashboard actions for completed, partial, cancelled, and remind-later
  confirmation outcomes.
- Added `partial` as a care-entry status and stores confirmation timestamp,
  confirming user, and optional confirmation note.
- Added per-user notification preferences for in-app, Web Push, and future email
  channels.
- Added optional Web Push subscriptions with privacy-preserving notification
  payloads.
- Added external-calendar source classification and explicit holiday-block
  derivation from imported all-day holiday source events.

## Security

- Web Push remains optional and disabled unless VAPID keys are configured.
- Push payloads do not include child names, exact care times, locations, notes,
  evidence references, trips, or costs.
- Stored push subscription endpoints are restricted to HTTPS hosts configured
  via `WEB_PUSH_ALLOWED_ENDPOINT_HOSTS`.
- Service-worker notification clicks are constrained to same-origin URLs.

## Upgrade notes

- Database migration `016_care_confirmations_notifications.sql` adds care
  confirmation tables, notification preferences, push subscriptions, and care
  entry confirmation fields.
- Optional new environment variables:
  `WEB_PUSH_SUBJECT`, `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY`, and
  `WEB_PUSH_ALLOWED_ENDPOINT_HOSTS`.
- Email preferences are stored for future use; this release does not send email.
- Publishing this release does not update `latest`; `latest` remains
  production-only and moves only with the production promotion workflow.
