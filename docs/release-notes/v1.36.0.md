# v1.36.0

`v1.36.0` updates the supported runtime and strengthens calendar subscription,
authorization, privacy, accessibility, compliance, and optional demonstration
workflows in the self-hosted application.

## Runtime and maintenance

- The supported application and container runtime moves to Node.js 26 LTS with
  npm 12.2.2. This release retains a bounded Node.js 24 rollback-compatibility
  check; Node.js 24 is not the published production baseline.
- Compatible application, build, browser-test, container-scan, and GitHub
  Actions dependencies are updated after compatibility and vulnerability
  review.
- The release process now validates a reviewed third-party software inventory,
  license policy, notices, and source/image SBOMs.

## Calendar and interface

- Personal calendar-feed links receive explicit lifecycle controls and
  dataminimal delivery diagnostics. Existing active links are not rotated by
  the upgrade.
- Month navigation, form guidance, responsive layouts, focus behavior, and
  accessibility checks are consolidated across the affected calendar and
  settings workflows.

## Security and privacy

- Scoped care-data mutations revalidate the current member scope inside the
  database transaction before changing domain records.
- Obsolete local browser identity state is cleared when account relationships
  change.
- Privacy-action previews and completed results are bound to the current
  domain-data generation. An earlier completed result is not reused after an
  in-application replacement or deletion.
- Current deployment and operator artifacts no longer include the retired
  authentication-proxy topology.

## Optional demonstration mode

The release contains an optional controlled demonstration capability. It is
disabled by default and uses explicit public projections, locally authorized
tester access, bounded side effects, transactional resets, and protected
operational status. Publishing this release does not activate the capability,
replace existing data, modify infrastructure, or authorize public exposure.

## Upgrade notes

- Migration `038` is applied automatically on SQLite and PostgreSQL to track
  the domain-data generation used by privacy-action execution.
- Existing calendar feed URLs and event identifiers remain valid unless access
  is explicitly replaced, revoked, or removed through membership changes.
- Review the updated runtime requirements before upgrading custom deployments.
- Back up the selected database before upgrading and retain the previous image
  and configuration for the documented rollback path.

The Helm chart is `0.17.0` with application version `1.36.0`. The release is
published first to `testing`. Promotion to `production` or `latest` requires a
separate explicit approval.
