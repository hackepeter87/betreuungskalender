# v1.7.3 - Planned-vs-actual care follow-up fixes

## Summary

`v1.7.3` finishes the immediate post-`v1.7.0` product follow-ups for planned
vs. actual care documentation. It keeps the existing data model and focuses on
making the already introduced fields usable and consistent.

## Changes

- Partial care can now be documented from the normal care-entry form with:
  - actual children;
  - actual start and end time;
  - actual responsible care party.
- Normal care-entry API updates now persist partial actual-care fields instead
  of only preserving values that came from the confirmation workflow.
- Holiday allocation now uses the configured default responsible care party
  when no explicit care entry exists inside a holiday block.
- Entry rows now have stable test IDs for regression coverage.

## Upgrade notes

- No new environment variables are required.
- No new migration is required; this release uses fields already introduced in
  the `v1.7.x` planned-vs-actual data model.
- Publishing this release does not update `latest`; `latest` remains
  production-only and moves only with the production promotion workflow.
