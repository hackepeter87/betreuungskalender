# v1.6.0 - Flexible recurrence and UI hardening

## Summary

`v1.6.0` replaces template-first contact-rule setup with a flexible,
RRULE-compatible recurrence builder. Users can define daily, weekly, and
monthly recurring contact rules through normal form controls, preview the
resulting calendar dates, and save them directly into the planned calendar.

The release also hardens several UI layouts in Settings, external holiday
calendar import, calendar feeds, and unavailability forms.

## Changes

- Contact rules now support bounded RRULE-compatible recurrence lines for
  daily, weekly, and monthly schedules.
- The contact-rule UI now exposes frequency, interval, weekday, monthly day,
  monthly ordinal, and multiple time-span controls instead of leading with fixed
  templates.
- Rule previews update from the real recurrence expansion before saving.
- Saving a rule still synchronizes planned entries automatically and preserves
  manually edited or cancelled generated occurrences.
- Settings user assignments and care-party rows use a compact aligned layout.
- External holiday-calendar import uses a controlled file chooser row with
  source name, color, selected file summary, and import action.
- Calendar feed actions and disabled states are aligned for desktop and mobile.
- The unavailability form groups start and end date/time controls and shows
  impact toggles as stable option cards.
- The default generated care-party label is localized to `Hauptbetreuung` for
  new databases and existing default rows that were still named
  `Primary caregiver`.

## Security

- Recurrence parsing uses the maintained `rrule` package instead of custom
  RRULE parsing.
- Server validation accepts only supported daily, weekly, and monthly
  recurrence schedules.
- RRULE schedule lines, interval, count, and schedule-line count are bounded to
  prevent excessive expansion.
- Browser users configure recurrence through controls; raw RRULE input is not
  exposed in the UI.

## Upgrade notes

- A new migration localizes only the original default care-party row. It does
  not rename user-created care parties.
- Existing `weekly` and `monthlyByWeekday` contact-rule JSON remains readable
  and continues to synchronize planned entries.
- Existing legacy contact-pattern data remains supported through the existing
  migration and compatibility fields.
- No environment variable changes are required.
- No production promotion is performed by publishing this release. The `latest`
  image tag remains production-only and moves only with the production
  promotion workflow.
