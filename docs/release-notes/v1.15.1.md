# v1.15.1

`v1.15.1` corrects holiday allocation, calendar month scoping, and recurring
contact-rule synchronization. It also includes the first-use setup layout fix
and runner updates merged after `v1.15.0`.

## Fixed

- Holiday statistics now count each calendar day once. Explicit actual or
  planned care takes precedence, while uncovered child shares use the configured
  primary care party.
- Multiple children split a holiday day into proportional shares, overlapping
  holiday periods no longer duplicate totals, and duplicate entries for the
  same party do not inflate allocation.
- Calendar agenda groups stay within the selected month. Holiday periods that
  cross month boundaries remain visible only on days inside that month.
- Bounded recurring contact rules synchronize from their configured start date
  through their end date. Existing rules can be synchronized explicitly without
  changing their definition.
- First-use setup fields remain aligned on wide screens.

## Changed

- Bounded contact-rule synchronization is limited to 36 months. Open-ended
  rules retain their rolling future horizon.
- Manual changes, cancellations, and generated-entry occurrence keys remain
  preserved during synchronization.
- Multiple due care confirmations produce at most one generic push per user and
  sweep. Every confirmation remains available as an individual in-app task.
- Release checks now verify the README release link together with package,
  lockfile, release notes, and deployment examples.
- Continuous-integration actions use the current Node.js runner support.

## Security

- The new synchronization action uses the existing write rate limit, role and
  care-party authorization, bounded expansion, and transactional idempotent
  synchronization.
- Push notifications remain generic and contain no child names, care times, or
  other sensitive care data.

## Upgrade notes

- No new schema migration is introduced by this patch. It includes migration
  `025_primary_care_party_setting.sql`, already merged after `v1.15.0`, which
  initializes the primary care-party setting without changing existing entries,
  rules, or holiday periods.
- Holiday totals may decrease for installations with several children because
  totals now represent calendar days rather than child-days.
- Existing bounded rules are not expanded retroactively during startup. Use
  **Synchronize entries** on the contact-rule page when historical occurrences
  should be added.
- Existing backups and calendar feed tokens remain compatible.
