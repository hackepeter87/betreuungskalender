# v1.16.0

`v1.16.0` adds secure link-based onboarding for fresh native OIDC
installations and invited application members.

## Added

- Native OIDC login transactions now distinguish normal login, initial owner
  setup, and invitation acceptance with a constrained server-side context.
- A fresh installation can bind the first authenticated OIDC user as owner by
  opening `/setup?token=...` with a configured one-time token.
- Invitation links at `/invite?token=...` start OIDC login when needed and
  assign the invitation role after the validated callback.
- Owner token use, owner claim, and rejected reuse are recorded without token
  values.

## Changed

- Claiming the owner link creates the admin membership and records the owner,
  but the existing first-use wizard remains responsible for completing setup.
- Invitation emails use the link-based flow. Existing manual token acceptance
  remains available as a compatibility fallback.
- Existing group-derived authorization and existing native OIDC sessions remain
  compatible.

## Security

- Raw setup and invitation tokens are never stored in SQLite. OIDC login state
  contains only a validated SHA-256 digest for onboarding contexts.
- Setup and invitation query strings are redacted before application request
  metadata is logged. Reverse proxies must apply equivalent URL redaction.
- The owner link is accepted only while setup is incomplete, expires after the
  configured TTL, and can be consumed once.
- All onboarding callbacks retain state, nonce, PKCE, issuer, audience, token
  expiry, hardened cookie, and server-side session validation.

## Upgrade notes

- Migration `026_oidc_login_context.sql` classifies existing login states as
  normal login and adds constrained hash-only onboarding context.
- Migration `027_owner_setup_tokens.sql` stores owner token hashes and
  single-use consumption metadata. Existing app data is not modified.
- For a fresh native OIDC installation, mount a token file at
  `OWNER_SETUP_TOKEN_FILE` and open the one-time setup link before
  `OWNER_SETUP_TOKEN_TTL_SECONDS` expires. Do not place the raw token in an env
  file, Compose file, log, or repository.
- Existing installations that are already set up reject owner setup links.
- Existing memberships, invitations, sessions, backups, and calendar feed
  tokens remain compatible.
