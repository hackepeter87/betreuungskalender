# v1.24.0

`v1.24.0` aligns calendar ranges, recurring care workflows, and report periods
throughout the self-hosted application.

## Calendar and time ranges

- Date and time validation now uses one shared range model in the browser and
  on the server.
- The month grid loads its complete visible six-week range, including care on
  adjacent-month days.
- ISO week numbers and an accessible overflow view make dense days navigable by
  mouse, touch, and keyboard.
- Holiday-source events are shown as normalized holiday periods instead of a
  second duplicate calendar item.

## Care workflow

- Planned overlaps are previewed before saving and remain available for review
  without producing reminder pushes while unresolved.
- A recurring occurrence can be replaced by a manual exception after the
  overlap is checked again transactionally.
- Past recurring dates can be previewed and synchronized for a selected range.
  Existing entries and manual exceptions are preserved, and the same preview
  fingerprint is required for the write.
- Backfilled past dates remain planned for review and do not create automatic
  confirmation reminders.

## Reports

- Custom report periods reload from a consistent server-side snapshot.
- Report content, statistics, data timestamp, report ID, print output, and PDF
  output use the same snapshot.
- A failed refresh keeps the previous result visible but clearly marks it as
  outdated.

## Compatibility

Migration `031_historical_contact_rule_sync` adds a reminder-suppression marker
for explicitly backfilled past recurring dates. Existing entries, rules,
sessions, invitations, backups, and portable transfer packages remain valid.

The Helm chart is updated to `0.5.0` with application version `1.24.0`.

## Validation

The release is validated with unit and integration tests, browser checks on
phone, tablet, and desktop widths, runtime security tests, container and Helm
smoke tests, dependency auditing, and strict release checks.
