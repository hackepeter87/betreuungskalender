# v1.9.1 - Shared-care authorization hardening

## Summary

`v1.9.1` is a security-hardening patch for shared-care deployments. It
strengthens write boundaries for care entries and recurring contact rules when
non-admin users are assigned to specific care parties.

The public notes intentionally stay abstract because the repository is public.
No secrets, private data, database files, backups, exports, or deployment
values are included.

## Changes

- Care-entry updates and deletes now require access to the existing assigned
  care party before accepting a change.
- Contact-rule updates and deletes now require access to the existing assigned
  care party before changing, syncing, or deleting the rule.
- Shared-care regression coverage now verifies that one parent cannot alter
  another care party's entries or rules while legitimate own-party writes still
  work.
- The app-data reset path now clears confirmation and notification tables before
  dependent domain records, keeping E2E and demo reset flows reliable after the
  notification workflow introduced in `v1.7.x`.
