# v1.15.0

`v1.15.0` improves calendar-focused operation and external calendar handling.
It adds a collapsible desktop sidebar, supports external iCalendar feed URLs as
read-only overlays, and makes the interaction between recurring care rules and
holiday periods explicit in the UI and documentation.

## Added

- Added a collapsible desktop sidebar so wide calendar views can use more of the
  screen while navigation remains available.
- Added external calendar feed URLs:
  - add a HTTPS iCalendar feed from Settings
  - refresh a stored feed
  - replace a stored feed URL
  - disable or delete the source like existing imported calendars
- Added visible markers and agenda text when a recurring rule date falls inside
  a holiday period.

## Changed

- External calendar sources now track whether they came from a local ICS file or
  a URL feed.
- Imported and fetched external events remain read-only overlays. They do not
  affect reports, holiday allocation, care confirmations, or care statistics by
  themselves.
- Holiday periods are documented and surfaced as planning/reporting frames. They
  do not silently override recurring care rules or generated care entries.

## Security

- External feed URLs must use HTTPS.
- Obvious local/private feed hosts are rejected to reduce server-side request
  exposure.
- Feed downloads use timeout, size, and event-count limits.
- Full feed URLs are stored only server-side for refreshes and are returned to
  the UI only in redacted form.
- Feed fetch and parse failures return generic errors and keep existing events
  available.

## Documentation

- Updated external calendar documentation for file and URL sources.
- Updated data-model documentation for URL feed source metadata and holiday
  period behavior.
- Updated security documentation for external feed URL handling.
- Updated README feature summary for external calendar overlays.
