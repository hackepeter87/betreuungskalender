# v1.29.2

`v1.29.2` completes bounded processing and authorization safeguards across the
self-hosted application's planning, reporting, transfer, and authentication
workflows.

## Processing limits

- Calendar, planning, reporting, external-calendar, transfer, and related
  operations apply explicit single-record and aggregate limits before large
  collections are materialized.
- Partial care confirmations use the same supported-date and maximum-duration
  contract as regular care entries.
- Optional report audit history is returned completely up to its documented
  limit; larger selections are rejected instead of being silently truncated.
- Limit responses remain generic and do not include submitted domain values.

## Authentication and authorization

- First-use completion preserves an already established owner.
- Native OIDC login completion remains bound to the browser that initiated the
  flow, and existing sessions require a current active workspace membership.
- Compatibility planning routes and reduced schedule views apply the same
  care-party scope as the corresponding workspace APIs.

## Exports and dependencies

- All CSV export paths use one encoder that keeps stored text inert when opened
  in spreadsheet applications while preserving columns, quoting, Unicode,
  numbers, and booleans.
- The supported mail transport dependency is updated without changing the
  invitation-link contract.

## Compatibility and update

The Helm chart is `0.10.2` with application version `1.29.2`. This release has
no database migration or intentional API compatibility break. SQLite remains
the default persistence backend; PostgreSQL 16 through 18 remains optional.

The release is promoted to `testing` for published-image acceptance.
`production` and `latest` require separate approval and remain unchanged by the
testing promotion.
