# v1.29.0

`v1.29.0` makes the self-hosted application's appearance and responsive
controls more consistent. It adds optional light and dark appearance modes
alongside automated accessibility, translation, and visual regression checks.

## Appearance and responsive layout

- Choose System, Light, or Dark in settings. The preference stays in the
  current browser; System follows its operating-system appearance setting.
- Shared forms, section headings, status indicators, and action controls use
  common style definitions across settings, setup, calendar, dashboard,
  reporting, backup/transfer, and supporting pages.
- Long navigation labels and report headings remain readable at tablet widths.
  Wide report tables can be reached through labelled scrollable regions.
- Print and PDF output retain a light background independently of the selected
  screen appearance. Empty unavailability sections in PDFs no longer place
  their message over the table header.

## Maintenance and regression checks

- Styles have explicit layer and feature ownership. Duplicate declarations,
  catch-all override files, and size regressions are checked during development
  and the production build.
- Automated accessibility tests cover critical interactions. Browser tests
  also cover focus, keyboard navigation, responsive overlays, and light/dark
  rendering at representative phone, tablet, and desktop widths.
- German and English translation checks detect missing keys and placeholders
  before new interface changes are accepted.

These checks support accessibility maintenance; they do not replace manual
assistive-technology testing or certify conformance for every deployment.

## Compatibility and update

The Helm chart is `0.10.0` with application version `1.29.0`. This release
introduces no database migration, API change, or new required operator setting.
SQLite remains the default; the optional PostgreSQL backend retains its existing
configuration and single-application-replica boundary.

Use a verified backup appropriate to the configured database before updating.
Follow [the database guide](../database-backends.md) for backup and rollback
responsibilities. Appearance preferences do not change saved domain data.

The release is promoted to `testing` for published-image and real-device
acceptance. `production` and `latest` require separate approval and remain
unchanged by this release's testing promotion.
