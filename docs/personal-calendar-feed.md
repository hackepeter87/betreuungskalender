# Personal iCalendar feed

Betreuungskalender can create protected, read-only iCalendar feeds for the
signed-in user. Calendar clients can subscribe to the generated `.ics` URLs.
This is not CalDAV and does not allow edits from calendar applications.

## Access model

The feed uses a revocable per-user token:

- The token is generated by the authenticated app user for one selected feed
  scope.
- The database stores only a SHA-256 hash of the token.
- Rotating the feed URL revokes previous active tokens for the same user and
  scope.
- Revoking the feed immediately invalidates the current URL for the selected
  scope.
- The token grants access only to `/calendar/<token>.ics`, not to `/api/*`.

Treat the feed URL like a password. Anyone who has the URL can read the feed
until it is revoked.

## Scopes

New tokens can use these scopes:

- `all`: all active, non-cancelled care entries visible to the feed owner.
  In solo mode this is the whole calendar. In shared mode, non-admin users are
  limited to their assigned care parties.
- `party:<id>`: active, non-cancelled care entries assigned to one selected
  care party.
- `legacy`: existing pre-v1.5 tokens. These remain valid and keep their old
  `created_by` owner behavior until rotated or revoked.

The feed includes the care-entry location as an iCalendar `LOCATION` value so
subscribed calendars can show where the handover or care period is planned.
The feed deliberately excludes notes, evidence references, trips, costs, audit
data, internal actor history, and deleted or cancelled entries. Each event title
uses the children and care party assigned to that individual care entry:

```text
Kind bei Betreuer
Kind1 und Kind2 bei Betreuer
Kind1, Kind2 und Kind3 bei Betreuer
```

This format is the same for legacy, overall, and party-scoped feeds. Different
events in an overall feed can therefore name different care parties. Historical
entries whose active care party can no longer be resolved use the neutral
fallback `betreuender Person`. Account display names, email addresses, and
identity-provider claims are never substituted for the entry care party.

`X-WR-CALNAME` remains the separate calendar-level title. For party-scoped
feeds it identifies the selected care party; for the all-scope feed it
identifies the overall Betreuungskalender feed.

Events use stable UIDs derived from the care-entry ID and include start, end,
`LOCATION`, `DTSTAMP`, and `LAST-MODIFIED` values.

## Subscribe

1. Sign in to Betreuungskalender.
2. Open `Einstellungen`.
3. In `Persönlicher Kalenderfeed`, choose the feed scope.
4. Choose `Feed-URL erzeugen`.
5. Copy the URL shown directly after creation.
6. Add it as a subscribed calendar in the calendar application.

Common clients call this "calendar subscription", "subscribe by URL", or
"add calendar from URL". Do not import the file as a one-time static calendar
unless the client has no subscription mode.

## Refresh behavior

The feed advertises an hourly refresh interval with the interoperable

```text
REFRESH-INTERVAL;VALUE=DURATION:PT1H
X-PUBLISHED-TTL:PT1H
```

calendar properties. These properties are hints for the subscribing calendar
client. Betreuungskalender cannot start or schedule that client's background
jobs and therefore cannot guarantee an exact refresh time.

Nextcloud stores subscribed calendars in its own cache and refreshes them from
its background jobs. Its current WebCal job runs an individual subscription at
most once per hour, even when a feed requests a shorter interval. Nextcloud
must therefore use a working system cron configuration. An existing
subscription can retain a previously stored refresh interval; remove and add
the subscription again if it does not adopt the feed's current interval.

Use the feed status in Betreuungskalender to distinguish the two sides:

- If `Zuletzt abgerufen` advances, the calendar client fetched the feed. A
  stale view then points to client-side processing or caching.
- If `Zuletzt abgerufen` does not advance, check the subscribed URL, network
  access and the calendar client's background-job configuration.

The feed response uses `Cache-Control: no-store`. Do not include the feed URL
or token in support logs, screenshots or issue reports.

## Rotate or revoke

Use `Neue URL erzeugen` when the URL may have been shared unintentionally.
Existing calendar subscriptions using the old URL for that scope will stop
updating.

Use `Feed widerrufen` to disable the current selected feed. A revoked URL
returns `404`.

## Operations

The feed endpoint is rate-limited with `RATE_LIMIT_EXPORT_MAX` and
`RATE_LIMIT_WINDOW_MS`. Application request logging redacts
`/calendar/<token>.ics` paths before writing request metadata.
