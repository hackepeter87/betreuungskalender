# v1.7.2 - Notification center and post-v1.7 product groundwork

## Summary

`v1.7.2` packages the post-`v1.7.0` UI and product follow-up work currently on
`main`. The most visible change is a persistent in-app notification center for
open care-confirmation tasks.

## Changes

- Added a notification bell in the desktop sidebar and mobile header.
- Added a notification-center popover for open care-confirmation tasks.
- Open confirmation tasks can jump directly to the related care entry.
- Added browser regression coverage for the notification center.
- Added the default responsible care party setting used when no more specific
  care party is selected.
- Added calendar-visible holiday periods.
- Added planned-vs-actual groundwork for deviations, partial confirmations,
  externally blocked contact periods, and holiday allocation statistics.
- Updated entry, agenda, report, contact, analytics, CSV, and PDF surfaces to
  expose the new planned-vs-actual information consistently.

## Follow-up scope

Issues #195, #196, and #197 remain the next product stabilization scope. This
release includes groundwork already merged to `main`; `v1.7.3` must audit those
issues against the current implementation, finish missing guided workflows, and
close the issues only when their acceptance criteria are proven.

## Upgrade notes

- No additional environment variables are required.
- The release includes schema and UI behavior already present on `main` after
  `v1.7.0`; operators should test the confirmation center and planned-vs-actual
  report surfaces in demo before production promotion.
- Publishing this release does not update `latest`; `latest` remains
  production-only and moves only with the production promotion workflow.
